# The Fourth Sheet

Website and tooling for **The Fourth Sheet**, Nathan Booth's Brisbane consultancy for SMEs and not-for-profits:
*"Your accountant gives you three sheets. I give you the fourth."* Live at https://www.thefourthsheet.com.au/.

The site is plain HTML, CSS and JavaScript (no framework, no build step) on GitHub Pages. Python in `tools/` generates
everything data-driven:
- the month-end sample model behind the home dashboard (checked to add up);
- 24 months of history as a daily star schema for a cloud database, written as CSVs;
- eight example reports, worked out **from those CSVs for any period**, each as a web page, Excel, PDF and PowerPoint;
- the deliveries map data, the mock-up images and the game video.

Business decisions, placeholders, the to-do list and the go-live checklist are in the private project notes: OneDrive, `The 4th Sheet/Business/Project notes.md`.

Ground rules: sample data is labelled and adds up; no client results claimed; copy is technology agnostic; every number has
its workings; every report gets Excel, PDF and PowerPoint versions; data lives in OneDrive, not git.

## The report builder (`tools/fourthsheet/`)

Each report is worked out from the data for one period (a month), and every download is built from scratch in code;
there are no templates. Excel is written cell by cell, with values as data and every calculation as a formula. The PDF is
an HTML page printed by headless Chrome. PowerPoint is written slide by slide, with native charts.

```
python3 tools/report.py --list                                  # every report and the periods it can run for
python3 tools/report.py job-margins --period 2026-06            # Excel, PDF and PowerPoint for June 2026
python3 tools/report.py board --period 2026-08 --format pdf --out ~/Desktop
```

- `source.py`: where the data comes from. It reads the CSV folder today; a database source will slot in behind the same `table(org, name)` call.
- `period.py`: the period, and everything that hangs off it (the month before, the same month last year, financial year to date, the 24-month chart window, data status).
- `catalogue.py`: the eight reports. Every number and sentence is worked out from the data.
- `build.py`: runs a report and writes its files. `build_all()` builds every report for every period for the website.

**Which periods:** a report needs a year of history before its period. The data starts October 2024, so the dropdown runs from
October 2025 to the current month, which is marked incomplete. Runway and the board summary need the balance sheet, which starts at
the 31 July 2026 opening balance. The website shows each report at its latest closed month. The **Period** dropdown loads any other
period, and `report-<name>.html?period=YYYY-MM` links straight to one.

**Website downloads:** for now, the website's own sample downloads (`media/exports/`) are committed so every button works on
GitHub Pages; all other spreadsheets and decks stay out of git. A file is only rewritten when its content changes. Next step:
build them on request from the cloud database, or from Power BI with a Power Automate trigger.

## Where the private files and data live

Everything private is in OneDrive (`Projects/The 4th Sheet/`), backed up to the cloud and kept out of git:

```
Business/           Project notes.md (decisions, to-do, go-live checklist), business and project plans
Data/               data only (CSV), one folder per task:
                      Common/  Month-end dashboard/{SME trades, SME services, Not-for-profit}/
                      Deliveries map/  Live displays/  Reports/  Management pack template/
                      Health/  Legal/  Purchasing/  Retail/   (the dataset projects)
Data documentation/ schema.sql, what each table holds, Power BI build prompts (one per report), dataset READMEs
Dataset projects/   the Health, Legal and Purchasing scripts and docs (a separate project from the website)
Media/site media/   a two-way copy of media/ (tools/sync_media.py; newer wins)

```

Scripts find the Data folder automatically on the Mac (`~/Library/CloudStorage/OneDrive-Personal/...`) and on a Windows PC
(`%OneDrive%\Projects\The 4th Sheet`). To use another location, set `FOURTH_SHEET_DATA` to the `Data` folder.

## Getting a machine ready (Mac or Windows)

```
python3 tools/setup_machine.py        # Windows: py tools\setup_machine.py
```

One script, safe to re-run. It installs everything and switches on the git leak guard, which stops any commit with a password, key, data file or
personal detail. It also finds OneDrive and syncs `media/`, signs you in to Azure, lets the machine through the database firewall, and tests
the connection.

## The cloud database (`tools/database/`)

Azure SQL with a SQL login whose **password is never in git**: it comes from `FOURTH_SHEET_SQL_PASSWORD` (your environment or the
repo's git-ignored `.env`) or Azure Key Vault. A per-machine firewall, TLS 1.2, least-privilege roles, and staged all-or-nothing
loads with a load log. See [tools/database/README.md](tools/database/README.md).

- `azure_setup.py` creates and locks down the server and database.
- `load.py` loads the CSVs.
- `../datasets.py` prepares the Retail, Health and Legal datasets (trimmed, synthetic names, up to date, checked) for their own schemas.
- `document.py` writes the table-by-table guide and star-schema plan, with Claude prompts, to OneDrive.
- The report builder reads the database with `--source db`, and `python3 tools/report.py --compare-sources` proves it gives the same reports as the CSVs.

## Quick Start

Run from the repository root (`dataPortfolio`):

```
pip install -r requirements.txt && python3 -m playwright install chromium   # once
python3 tools/serve.py             # then open http://127.0.0.1:8765 (no caching)
python3 tools/sample_data.py       # regenerate the model, CSVs, every report for every period, all downloads (about 3 minutes)
python3 tools/check_exports.py     # recalculate every Excel formula and compare with the site's numbers
```

What `sample_data.py` runs, in order:
1. the model and home dashboard (`financial_model.py`, `publish_dashboard.py`);
2. the daily star schema and history (`warehouse.py`, `history.py`), then the supporting tables (`drivers.py`);
3. the deliveries map (`deliveries.py`);
4. the CSVs and `schema.sql` written to OneDrive;
5. the reports, read back from those CSVs (`fourthsheet`, `build_reports.py`);
6. the Power BI prompts (`powerbi_notes.py`);
7. `media/` synced with OneDrive (`sync_media.py`).

Shared look: `exportkit.py` (Excel and PDF) and `pptkit.py` (PowerPoint). Months lock on the 2nd working day of the next month (`data_status.py`, `AS_AT`).

## Prerequisites

- Python 3 available in PATH (`python`, `py -3`, or `python3` depending on platform), with `requirements.txt` installed.
- Google Chrome, or Playwright's Chromium, for the PDFs.
